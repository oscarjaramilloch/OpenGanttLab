Capítulo 1 · Comenzar

Introducción

OpenGanttLab convierte un cronograma en un Gantt comparable, una Línea de Tiempo lista para presentar y una tabla de datos editable. Todo en un solo archivo, sin instalación y sin conexión.

En este capítulo aprenderás a:
  • Entender qué hace OpenGanttLab y qué problemas resuelve.
  • Reconocer sus tres espacios de trabajo: Gantt, Línea de Tiempo y Datos.
  • Conocer los conceptos que se usan en todo el manual.

¿Qué es OpenGanttLab?

OpenGanttLab es una aplicación web para visualizar, comparar y presentar cronogramas de proyecto. Lee archivos Excel (.xlsx) con varios escenarios o archivos XML de Microsoft Project (incluso de más de 1 GB) y los muestra en tres formatos:

Gantt · Comparador de EscenariosBarras de Línea Base frente a Real/Proyectado, avance, ruta crítica y dependencias.
Línea de TiempoVista ejecutiva con hitos, barras y textos editables, lista para presentar.
DatosTabla editable con todas las tareas, carga de Excel/XML y gestión de escenarios.

Es una aplicación standalone: un único archivo HTML que se abre en el navegador. Los datos no salen de su computador.

¿Para quién está diseñado?

  • Planificadores y controladores de proyecto que comparan versiones de un cronograma (por ejemplo P10, P50 y P90).
  • Gerentes y líderes de proyecto que necesitan una lámina clara del cronograma para un comité.
  • Equipos de ingeniería y construcción que reciben cronogramas de Microsoft Project y quieren revisarlos rápido.

¿Qué problemas resuelve?

NecesidadCómo lo resuelve OpenGanttLab
Comparar la Línea Base con lo real o proyectadoEl Gantt dibuja ambas barras en la misma fila y muestra el avance como relleno.
Comparar varias versiones del cronogramaCada versión es un escenario: se gestiona, se duplica y se filtra desde la sección Datos.
Entender qué depende de quéLas dependencias se dibujan como flechas y se resalta la cadena completa de una tarea.
Presentar el cronograma a un comitéLa Línea de Tiempo permite editar colores, textos, hitos y formas, y exportar a PNG, PDF o PowerPoint.
Abrir un XML enorme de ProjectEl archivo se lee por partes y solo se conserva lo necesario.
Enviar el resultado sin enviar el Excel«Compartir» genera un HTML autónomo con los datos embebidos.

Cómo funciona por dentro

Los datos entran por Excel o Project XML, se convierten en una única Tabla de Datos y de ahí alimentan las vistas. Cualquier corrección en la tabla se refleja en el Gantt y en la Línea de Tiempo.

Conceptos principales

Estos términos aparecen en toda la aplicación. Encontrará definiciones completas en el glosario.

Escenario
Una versión del cronograma que se quiere comparar (por ejemplo «Plan base» o «P50»). Es el agrupador mayor: la columna Escenario. Si una tarea no la trae, se usa el archivo XML de origen y, en último caso, su Categoría 1.
Categoría 1 y Categoría 2
Los dos niveles con que se agrupan las tareas dentro de un escenario: Categoría 2 es la fase o agrupación dentro de una Categoría 1. Cada una tiene su propio color.
Línea Base (LB) y Real/Proyectado (R/P)
Cada tarea tiene dos juegos de fechas: los planificados originalmente (LB) y los reales o proyectados (R/P).
Hito y evento
Un hito es una tarea sin duración (un rombo). Un evento es un marcador que se dibuja sobre el eje de la Línea de Tiempo.
Dependencia
Una relación entre dos tareas: la predecesora condiciona a la sucesora, con un tipo (FC, CC, FF, CF) y un desfase opcional.
Navegador recomendado

Use Chrome o Edge (versión 86 o superior). Funciones como guardar los cambios directamente en el Excel usan una API propia de estos navegadores.

Software libre

OpenGanttLab se distribuye bajo la licencia GNU GPLv3: puede usarlo, estudiarlo, modificarlo y compartirlo. Las versiones modificadas que se distribuyan deben publicarse también bajo GPLv3, con su código fuente.

Capítulo 2 · Comenzar

Primeros pasos

En cinco minutos: abrir la aplicación, cargar su primer cronograma y recorrer el Gantt, la Línea de Tiempo y la Tabla de Datos.

En este capítulo aprenderás a:
  • Abrir OpenGanttLab y cargar su primer archivo.
  • Reconocer el flujo de trabajo completo.
  • Hacer un primer recorrido por las tres vistas.

Requisitos

  • Un navegador moderno: Chrome o Edge (versión 86 o superior).
  • Un archivo de cronograma: un Excel (.xlsx) con las columnas que se describen en Proyectos y datos, o un XML exportado desde Microsoft Project.
  • No requiere instalación ni conexión a internet. Solo la exportación a PowerPoint necesita internet la primera vez.

Abrir OpenGanttLab

Abra el archivo OpenGanttLab 3.1.html en el navegador. Aparece una pantalla de bienvenida con los datos del autor y la licencia.

El flujo de trabajo

Casi todo el trabajo sigue el mismo recorrido de cinco etapas. Puede repetir cualquiera de ellas: al corregir un dato, las vistas se actualizan.

Cargar su primer proyecto

  1. Vaya a DatosPulse Datos en el riel de navegación (a la izquierda).
  2. Cargue el archivoPulse el ícono Cargar archivo (flecha hacia arriba). La aplicación detecta sola si es un Excel o un XML.
  3. Elija el archivoSeleccione su .xlsx o su .xml. Las tareas aparecen en la tabla y, de inmediato, en el Gantt.
  4. Revise los datosCompruebe nombres, fechas y avance en la Tabla de Datos. Puede corregir directamente en ella.
  5. Abra el GanttPulse Comparador de Escenarios para ver el cronograma.
Atajo

Con el Gantt vacío, un clic sobre el área de trabajo abre un menú para vincular su Excel o importar un XML.

¿XML de Project?

Un XML necesita un paso más: el mapeo de columnas, donde se indica de qué campo del XML sale cada dato. Casi todo se mapea solo. Vea Importar desde Project XML.

Primer recorrido

  1. GanttActive Línea base para ver las barras rayadas junto a las de color, y Avance real para el relleno de avance. Detalles en Cronograma.
  2. DependenciasEn Capas active Dependencias y haga clic en una barra para resaltar su cadena.
  3. Línea de TiempoPulse Línea de Tiempo en el riel. Pruebe Vista C1, Ejecutivo y Vista Hitos. Detalles en Vistas.
  4. ExporteUse Exportar (PNG, PDF o PPTX) o Compartir para guardar un HTML autónomo. Detalles en Exportar y compartir.
Resultado esperado

Al terminar debería ver su cronograma en el Gantt, con los colores de cada Categoría 1 y Categoría 2, y poder pasar a la Línea de Tiempo sin volver a cargar nada.

Capítulo 3 · Comenzar

La interfaz

Un recorrido por la pantalla: riel de navegación, barra de herramientas, área de trabajo y barra de estado.

En este capítulo aprenderás a:
  • Identificar cada zona de la pantalla y para qué sirve.
  • Usar el riel de navegación y la barra de herramientas.
  • Controlar la escala, el zoom y el formato de fecha.

La pantalla principal

La pantalla se compone de un riel de navegación a la izquierda y, a su derecha, el espacio de trabajo de la sección elegida. En el Gantt el espacio de trabajo se divide en cinco zonas.

Riel de navegación

El riel tiene cinco secciones. Cada una abre su propio espacio con su propia barra de herramientas.

SecciónPara qué sirve
Comparador de EscenariosEl diagrama de Gantt: Línea Base frente a Real/Proyectado, por escenario.
Línea de TiempoLa vista ejecutiva para presentar, con edición libre.
DatosLa Tabla de Datos, la carga de archivos y la Gestión de XML.
ConfiguraciónTema, recordatorios y valores por defecto.
AyudaDocumentación, historial de cambios y enlace a este manual.
Más espacio

Pulse el botón « Colapsar para reducir el riel a íconos. La aplicación recuerda su elección.

Barra de herramientas

Cada sección tiene su barra. Hay dos tipos de controles: interruptores (se activan con un clic) y menús (íconos con una flecha ˅ que abren opciones). Pase el cursor sobre cualquier ícono para ver su nombre.

Barra que se adapta

La barra ajusta lo que muestra al ancho de la ventana: primero oculta las etiquetas, luego los accesos rápidos, y agrupa el resto en el menú Más herramientas (⋯). Ninguna función desaparece.

El menú Capas

Las capas deciden qué se dibuja sobre el cronograma. El número junto a «Capas» indica cuántas están activas.

CapaQué hace

Línea baseDibuja la barra de Línea Base junto a la Real/Proyectada.
Marca ActivityMuestra solo las tareas marcadas como «Activity».
ResumenIncluye las tareas resumen (viene apagado).
FechasEscribe las fechas junto a las barras y a los hitos.
DependenciasDibuja las flechas entre predecesoras y sucesoras.
Fecha de estadoDibuja una línea vertical en la fecha de corte.
Ruta críticaDeja visibles solo las tareas marcadas como críticas en los datos. Estas se dibujan siempre con borde rojo; la capa permite ajustar su grosor.

Barra de estado y escala

En la parte inferior hay dos bloques: un resumen del proyecto visible y los controles de escala.

El resumen sigue a los filtros

Las cifras de la barra de estado se calculan sobre las tareas que están visibles. Si filtra o desactiva escenarios, cambian.

Ayuda integrada

La sección Ayuda del riel abre la documentación dentro de la aplicación. Incluye un manual resumido, una referencia técnica, el historial de cambios y un enlace a este manual completo.

Capítulo 4 · Datos

Proyectos y datos

Cómo entran los datos a OpenGanttLab —Excel o Project XML—, cómo se revisan y se corrigen en la Tabla de Datos y cómo se ordenan por escenarios.

En este capítulo aprenderás a:
  • Preparar un Excel con las columnas correctas y cargarlo.
  • Importar un XML de Microsoft Project y mapear sus campos.
  • Editar, filtrar y guardar datos en la Tabla de Datos.
  • Escribir dependencias en el formato de Project.

Cargar un Excel

El archivo debe ser un .xlsx (el formato antiguo .xls no se puede leer; guárdelo antes como .xlsx). Debe tener una hoja con estas columnas. La primera fila que contenga «Nombre de Tarea» (dentro de las ocho primeras) se toma como encabezado.

ColumnaQué contieneObligatoria
idCampo ID: identificador de la tarea (se usa para las dependencias). El encabezado de la columna es «id» (no distingue mayúsculas).No
EscenarioLa versión del cronograma (agrupador mayor). Si su Excel usa la Categoría 1 para las versiones (P10, P50, P90), deje esta columna vacía: cada Categoría 1 cuenta como un escenario.No
Categoría 1Agrupación mayor de las tareas (frente, disciplina o variante).Sí
Categoría 2La fase o agrupación de la tarea.No
Nombre de TareaEl texto que se ve en el Gantt.Sí
Start LB · End LBInicio y fin de la Línea Base.Sí
Avance %De 0 a 100, o de 0,0 a 1,0.No
Start R/P · End R/PInicio y fin Real/Proyectado. Si faltan, se usan los de la Línea Base.No
Clase«Tarea», «Hito» o «Evento». Una tarea con inicio y fin de LB iguales se toma como hito.No
Ruta Crítica«Si» o «No».No
Marca Activity · Resumen«Si» o «No».No
Predecesoras · SucesorasDependencias en el formato de Project (ver más abajo).No
Filas que se omiten

Una fila se omite si le falta el Nombre de Tarea, la Categoría 1 o alguna fecha de Línea Base. Si faltan tareas después de cargar, revise primero esas tres columnas.

Puede partir de una plantilla vacía con el ícono Descargar plantilla de la barra de la Tabla de Datos.

Excel vinculado

Cuando el navegador lo permite (Chrome o Edge), el Excel queda vinculado. Aparecen entonces dos botones nuevos: Actualizar, que recarga el archivo con los últimos cambios guardados en Excel, y Guardar cambios en el Excel vinculado, que escribe la tabla en el mismo archivo.

Autoguardado

Si hay un Excel vinculado (o un archivo elegido con «Compartir») y ya concedió permiso de escritura, la aplicación guarda los cambios sola cada 5 minutos. Sin destino vinculado no guarda nada: el aviso de «cambios sin compartir» es la única señal.

Importar desde Project XML

El XML de Project se gestiona en Datos → Gestión de XML (la tercera pestaña de la sección). Tiene cuatro pestañas: Cargar XML, Base de datos, Mapeo de columnas y Vista previa.

  1. Cargue uno o varios XMLEn la pestaña Cargar XML arrastre los archivos o haga clic para elegirlos. Una barra muestra el avance de lectura.
  2. Revise la base de datosLa pestaña Base de datos lista cada archivo cargado con su nombre de variante (editable), su cantidad de tareas y su «LB actual».
  3. Configure el mapeoEn Mapeo de columnas indique de qué campo del XML sale cada dato de la tabla. La mayoría se mapea automáticamente.
  4. Compruebe con la vista previaLa pestaña Vista previa muestra las primeras tareas con el mapeo aplicado.

Cómo funciona el mapeo

Para cada campo de la tabla puede elegir:

OpciónEfecto
Una columna del XMLToma el valor de esa columna en cada tarea (incluye los campos personalizados del proyecto).
★ Variante del archivoUsa el nombre de la carga como valor.
✏ Valor fijoEscribe un texto que se aplica a todas las tareas del archivo.
— No mapear —Deja el campo vacío.

Los campos Categoría 1, Categoría 2 y Nombre de Tarea son obligatorios. Cuando están completos, los datos pasan solos a la Tabla de Datos; no hay botón de aplicar.

  • Si Escenario está en «Valor fijo», la carga se renombra con ese valor y viceversa.
  • Copiar al [n] copia el mapeo al siguiente archivo.
  • El botón + crea un mapeo personalizado: una columna extra con nombre editable que aparece en la tabla y en el Gantt. Dura solo la sesión.
Líneas base 0–10

Project guarda hasta 11 líneas base. OpenGanttLab guarda el inicio y el fin de todas y usa por defecto la de fecha de guardado más reciente (la «LB actual»). El mapeo automático de Start LB y End LB usa esa línea.

Las columnas personalizadas no viajan

Los mapeos personalizados existen solo durante la sesión: no se guardan con Compartir ni se exportan a Excel.

Devolver los cambios a Project (XML)

Los cambios que haga en la Tabla de Datos se pueden llevar de vuelta a Microsoft Project. OpenGanttLab no reemplaza el archivo: vuelve a leer el XML original por partes y crea un XML nuevo en el que solo cambian las tareas que usted editó. El resto del archivo pasa sin alteraciones y funciona también con archivos de más de 1 GB.

  1. Edite en la Tabla de DatosCambie nombres, avance, fechas, predecesoras o campos personalizados de las tareas del XML.
  2. Pulse «Guardar cambios en un XML de Project»Está en Datos → Gestión de XML → Base de datos, en la fila del archivo (ícono de documento con flecha).
  3. Elija el XML original y el destinoLea el aviso y pulse Continuar. Elija el XML original del proyecto y luego dónde guardar el nuevo (propone «…_editado.xml»).
  4. Revise el resumen y abra el resultado en ProjectLa aplicación indica cuántas tareas se modificaron y qué no se pudo devolver.

Qué se devuelve y qué no

Cambio en la tablaQué se escribe en el XML
Nombre de TareaEl nombre de la tarea.
AvanceEl porcentaje completado.
Start R/P y End R/PLas fechas de inicio y fin; la tarea pasa a programación manual (ver más abajo).
PredecesorasLos vínculos con su tipo y desfase en días; el ID se convierte al UID de Project.
Campos personalizadosEl valor del campo. Las Categorías 1 y 2 solo si vienen de un campo personalizado del proyecto.

No se devuelve: la Línea Base, Clase, Ruta crítica y Resumen (incluidas las fechas de las tareas resumen), las filas nuevas o eliminadas en la tabla, los desfases en porcentaje y los escenarios creados con «Duplicar escenario».

Fechas: programación manual y duración aproximada

Project recalcula las fechas de las tareas con programación automática, por lo que OpenGanttLab marca como manual cada tarea cuyas fechas cambió. La duración se conserva si el largo de la tarea no cambia; si cambia, se ajusta de forma proporcional (aproximada), porque la aplicación cuenta días corridos y Project usa calendarios laborales. Si una tarea no trae los elementos de programación manual, sus fechas no se devuelven y el resumen lo indica.

Compruebe el resultado en Project

La aplicación verifica que cada tarea modificada siga siendo XML válido y que solo cambien las tareas editadas, pero aún no se ha comprobado abriendo el resultado en Microsoft Project. Ábralo y revíselo antes de usarlo. No cambie el mapeo entre editar y guardar.

Requisitos

Necesita Chrome o Edge (API de acceso a archivos). El XML original debe estar en UTF-8; el de destino es un archivo nuevo, y el original no se modifica.

La Tabla de Datos

La tabla contiene todas las tareas y es el lugar para corregir datos. Los cambios se aplican solos.

  • Editar: haga clic en una celda y escriba. El Gantt y la Línea de Tiempo se actualizan al salir de la tabla, no en cada tecla.
  • Agregar o eliminar filas: Agregar fila al final; el ícono de papelera al final de cada fila la elimina.
  • Deshacer, rehacer y restaurar: Restaurar vuelve a los datos originales del XML y descarta los cambios manuales (se puede deshacer).
  • Ancho de columna: arrastre el borde derecho del encabezado.
  • Tablas grandes: desde 250 filas solo se dibujan las visibles, así que sigue fluida con miles de tareas.

Duración y reprogramación de sucesoras

La columna Duración (d) muestra los días corridos de cada tarea (fin − inicio + 1; los hitos y eventos valen 0). Al editar una fila, la tabla puede reprogramar sus sucesoras como lo hace Project con programación automática.

  • Qué dispara la reprogramación: cambiar Start R/P, End R/P, Duración o Predecesoras de una fila.
  • Qué se mueve: las sucesoras de esa fila, dentro de su escenario, lo antes posible según sus vínculos (FC, CC, FF, CF y desfase). Se empujan y también se adelantan.
  • Mover el Start R/P conserva la duración (corre también el End R/P); editar el End R/P o la Duración la cambia.
  • Lo que no se mueve: las tareas con avance 100 %, las tareas resumen y la Línea Base. Las de 100 % y las resumen siguen valiendo como predecesoras.
  • Deshacer: la edición y todo lo reprogramado son un solo paso de historial.
  • Ciclos: si hay un ciclo de dependencias no se reprograma nada y aparece un aviso.
Días corridos

La reprogramación usa días corridos, sin calendario laboral. Puede apagarla con el interruptor Reprogramar sucesoras de la barra (viene encendido y la aplicación recuerda su elección en este navegador).

Dependencias: ID, Predecesoras y Sucesoras

Las tres últimas columnas de la tabla sirven para las dependencias. ID identifica la tarea, Predecesoras se escribe a mano o viene del XML, y Sucesoras se calcula sola (es la inversa de las predecesoras).

La columna Predecesoras usa el mismo formato que Microsoft Project: el número de la predecesora, el tipo de vínculo y un desfase opcional.

EjemploSignificado
12La tarea 12 debe terminar antes de que empiece esta (Fin a Comienzo).
12CC+2 díasComienzo a Comienzo con 2 días de retraso.
7FF-1 díaFin a Fin con 1 día de adelanto.
12;15FC+3dDos predecesoras, separadas por «;».
Ámbito de los ID

El ID solo tiene que ser único dentro de su Escenario. Si Escenario está vacío se usa un nombre generado: la variante del archivo XML o, en Excel, la Categoría 1. En un XML los ID se buscan en todo el archivo; en Excel, un ID único en todo el archivo también puede enlazar entre escenarios.

Filtrar la tabla

El ícono Filtro muestra u oculta los botones de embudo de cada encabezado. Los filtros de cada columna se explican en Filtros y orden. Además, el segmentador de escenario (a la derecha de la barra) muestra en la tabla solo las filas del escenario elegido; «Todos (N)» las muestra todas.

Capítulo 5 · Visualizar

Cronograma: el Gantt

El Comparador de Escenarios: barras de Línea Base y Real/Proyectado, avance, ruta crítica, dependencias y todas las herramientas de lectura del diagrama.

En este capítulo aprenderás a:
  • Leer el Gantt: barras, hitos, avance y Línea Base.
  • Activar y entender las dependencias y sus tipos.
  • Resaltar la cadena de una tarea y revisar los avisos.
  • Mostrar columnas adicionales y usar los tooltips.

Cómo leer el Gantt

Cada fila es una tarea o un hito, agrupada por Categoría 1 y Categoría 2. A la derecha, el eje de tiempo muestra las barras.

Un vistazo rápido

Si la barra de color empieza o termina después de la rayada, la tarea se desplazó respecto al plan. La diferencia es el desplazamiento.

Detalle al pasar el cursor

Al pasar el cursor sobre una barra o un hito aparece un cuadro con su nombre con el ID (si tiene), sus fechas, avance, si es crítica y —si tiene— sus predecesoras y sucesoras, cada una con su ID, tipo de vínculo y desfase. Lo mismo aparece en la Línea de Tiempo.

Dependencias

Una dependencia relaciona dos tareas: la predecesora condiciona a la sucesora. OpenGanttLab admite los cuatro tipos de Project.

TipoSigla en inglésSignificado
FC · Fin a ComienzoFSB empieza cuando termina A. Es el tipo por defecto.
CC · Comienzo a ComienzoSSB empieza cuando empieza A.
FF · Fin a FinFFB termina cuando termina A.
CF · Comienzo a FinSFB termina cuando empieza A.

Ver las flechas

  1. Abra CapasPulse Capas en la barra de herramientas.
  2. Active DependenciasLas flechas se dibujan entre las tareas visibles. Gris = normal; rojo = entre dos tareas de la ruta crítica.
  3. Resalte una cadenaHaga clic en una barra o en un hito: se marcan en azul todas sus predecesoras y sucesoras (directas e indirectas) y el resto se atenúa.
Solo con el interruptor encendido

El resaltado de cadena funciona con Dependencias activo. Cambiar el interruptor reinicia la selección.

Avisos de dependencias

Cuando hay algo que revisar aparece un ícono de triángulo junto a las capas, con el número de avisos.

AvisoCausa
Predecesoras inexistentesUna predecesora apunta a un ID que no existe en su escenario.
CiclosDos o más tareas dependen entre sí (A depende de B y B de A).
AutorreferenciasUna tarea se lista a sí misma como predecesora.
Formato no reconocidoParte del texto de la columna Predecesoras no tiene el formato de Project.
Conflictos de fechas opcionalLas fechas de la sucesora contradicen el vínculo (ver abajo).

Conflictos de fechas

Un conflicto ocurre cuando la sucesora empieza o termina antes de lo que permite el vínculo. Por ejemplo, con un vínculo FC, B empieza antes de que termine A.

Viene apagado

En la práctica una tarea puede empezar antes que su predecesora por estrategia. Por eso el aviso es opcional: actívelo en Configuración → Datos y métricas → «Avisar de conflictos de fechas». Compara las fechas Real/Proyectado y tolera 1 día.

Mostrar u ocultar columnas

Haga clic derecho sobre un encabezado de columna para abrir el menú Mostrar / Ocultar. Es una sola lista con todas las columnas de la Tabla de Datos.

  • Las columnas agregadas quedan fijas a la izquierda, a continuación de «Nombre de Tarea», con su propio botón de filtro.
  • Ajustar texto: activo, el texto se ajusta a 2 líneas; inactivo, se corta con «…». La preferencia se guarda por columna.
  • La altura de cada fila se ajusta sola al contenido.
  • Arrastre el borde derecho de un encabezado para cambiar el ancho de la columna.

Colores

Un clic en una celda de Escenario, Categoría 1 o Categoría 2 abre un selector de color. El color de Categoría 2 es el de sus barras. Los colores por defecto se definen en Configuración.

Fecha de estado y hoy

La capa Fecha de estado dibuja una línea vertical en la fecha de corte del proyecto, con estilo, grosor y color configurables. El botón de reloj de la barra inferior lleva la vista a la fecha de hoy.

Capítulo 6 · Visualizar

Vistas: la Línea de Tiempo

La Línea de Tiempo presenta el cronograma para un comité: cuatro modos de vista, edición libre de colores y textos, formas, dependencias y exportación.

En este capítulo aprenderás a:
  • Elegir el modo de vista adecuado: Comparador, Segmentación, Ejecutivo, Vista C1 o Vista Hitos.
  • Editar barras, hitos y textos sin alterar los datos.
  • Insertar textos y formas libres.
  • Mostrar dependencias en la Línea de Tiempo.

Los modos de vista

En Capas, la sección Contenido decide qué elementos se muestran y la sección Modo de vista decide cómo se dibuja el diagrama. Todos usan los mismos datos. Sin ningún modo activo, la Línea de Tiempo muestra su vista base: una barra por tarea sobre el eje de años, con los hitos sobre el eje.

Un doble clic sobre una barra abre su panel de edición.

Lo visual no cambia los datos

Editar el texto o el color en la Línea de Tiempo solo afecta la presentación. El dato real de la tabla, del Gantt, del Excel y del XML no se toca. La única excepción es la sección Dependencias descrita abajo.

Dependencias desde el panel

En tareas, hitos y eventos, el panel incluye la sección Dependencias (expandida por defecto):

  • ID: el identificador de la tarea (solo lectura).
  • Predecesoras y Sucesoras: campos editables con el formato de Project, por ejemplo 12; 15CC+2 días. Confirme con Enter o saliendo del campo.

A diferencia del resto del panel, estos cambios sí modifican los datos: se escriben en la columna Predecesoras de la Tabla de Datos (las sucesoras editan las predecesoras de las tareas indicadas) y se pueden deshacer con el deshacer de la tabla. Si la reprogramación automática está activa, las sucesoras se reprograman como al editar la tabla. Un formato no válido o un ID inexistente se avisa y se ignora. Para definir sucesoras, la tarea debe tener ID.

Ocultar una línea de precedencia

Con Dependencias encendido en la Línea de Tiempo, haga clic sobre una flecha: se resalta con un halo azul. Pulse Delete (o Backspace) para ocultarla; el resto de flechas no cambia. Para volver a verla, abra Tareas ocultas (N), sección Líneas de precedencia, y restáurela con el ojo, o use Restaurar todas. Es solo visual: los vínculos siguen en los datos, el Gantt, el Excel y el XML, y el halo de selección no sale en los exportes. Con una barra seleccionada solo se dibuja su cadena azul y las demás flechas no se pueden seleccionar.

Ejecutivo: ocultar tareas

  1. Active EjecutivoEn Capas → Modo de vista.
  2. Oculte una tarea de esta vistaSelecciónela con un clic y pulse Delete, o use doble clic → Ocultar de Ejecutivo.
  3. Recupere lo ocultoAparece el botón Tareas ocultas (N): ábralo para restaurar una tarea o todas.
Persistencia

Las tareas ocultas y el formato de fecha se guardan por proyecto en el navegador y también viajan con «Compartir».

Vista C1: bandas por Categoría 1

  • Cada banda tiene una etiqueta vertical con el nombre de su Categoría 1.
  • La etiqueta se puede seleccionar y arrastrar hacia arriba o abajo para reordenar las bandas, con una vista previa en vivo.
  • El borde derecho de la columna de etiquetas y el borde inferior de cada banda se arrastran para ajustar su ancho y alto.
  • Un doble clic en la etiqueta abre el panel de edición del texto (solo visual).

Edición: textos y formas libres

El menú Editar agrega elementos propios sobre el diagrama.

  • Formas: se arrastran, se redimensionan con las asas de las esquinas y giran libremente. Pueden llevar texto dentro, que se mantiene horizontal aunque la forma gire.
  • Panel de forma: relleno, borde y grosor; texto con tamaño, alineación y posición; y valores numéricos de ancho, alto, posición y giro.

Dependencias en la Línea de Tiempo

Active Dependencias en Capas → Contenido. Usa los mismos datos, tipos y colores que el Gantt.

  • Se dibujan en la vista base y en el Comparador (en las dos secciones, cada una con sus barras).
  • No se dibujan en Ejecutivo ni en Vista Hitos; al volver a la vista base reaparecen.
  • Solo se conectan tareas visibles: las ocultas (Delete, filtros) no tienen flecha.
  • El resaltado por clic funciona con el interruptor encendido.

Ajustes del área de visualización

El menú Ajustes controla el espacio extra a izquierda, derecha, arriba y abajo, el alto de las barras, el tamaño de los rombos, y el alto y ancho de la fila de años. El formato de fecha (14 formatos, por ejemplo dd/mm/aa o mmm/aaaa) se elige en el selector de la barra inferior. Abajo a la derecha hay una barra de zoom de 25 % a 400 %; pulse el porcentaje para volver a 100 %.

Capítulo 7 · Analizar

Escenarios

Un escenario es una versión del cronograma. Aprenda a cargar varias versiones, elegir cuáles ver y compararlas en el Gantt y en la Línea de Tiempo.

En este capítulo aprenderás a:
  • Entender qué es un escenario en Excel y en XML.
  • Cargar, duplicar y eliminar escenarios.
  • Elegir qué escenarios se ven y compararlos.

Qué es un escenario

Un escenario es una versión del cronograma que quiere comparar: un plan base y una replanificación, o las variantes P10, P50 y P90 de una simulación. Cada escenario tiene sus propias tareas.

El escenario de una tarea se determina así, en este orden:

  1. La columna Escenario de la tarea, si tiene valor.
  2. Si no, el archivo XML de origen (cada XML cargado cuenta como un escenario, con el nombre de su variante).
  3. Si no, su Categoría 1. Así, un Excel antiguo que usa la Categoría 1 para las versiones sigue funcionando sin cambios.
Escenario y dependencias

El escenario es también el ámbito de los ID de las dependencias: dos escenarios pueden repetir los mismos ID sin mezclarse.

Gestión de escenarios

La sección Datos tiene una pestaña Gestión de escenarios con la lista de todos los escenarios de la sesión, vengan de Excel o de XML.

ÍconoQué hace
Ver en la Tabla de DatosAbre la tabla filtrada por ese escenario (con el segmentador).
Duplicar escenarioCrea una copia idéntica (fechas, avance, dependencias y campos) con un nombre nuevo.
Eliminar escenarioQuita el escenario y todas sus actividades, con confirmación.
  1. Pulse Duplicar escenarioLa aplicación propone un nombre («… (copia)»).
  2. Escriba el nombre y confirmeLa copia aparece en la Tabla de Datos, con sus predecesoras resueltas dentro de la copia.
  3. Edite la copiaCambie fechas, avance o dependencias en la Tabla de Datos, filtrando por el escenario nuevo con el segmentador.
Ideal para simular

Duplique «Plan base», mueva fechas en la copia y compárelas en el Gantt. Las copias sobreviven a un nuevo «Aplicar mapeo» del XML.

Eliminar borra las tareas

Eliminar un escenario quita todas sus actividades de la tabla. Puede deshacerlo desde la Tabla de Datos con Deshacer.

Cargar varios escenarios

  1. Cargue cada varianteEn Datos → Gestión de XML cargue un XML por variante (o varios a la vez). Con Excel, use una fila por tarea y escenario, con la versión en la columna Escenario.
  2. Nombre la cargaEn la pestaña Base de datos del XML edite el nombre de la variante (por ejemplo «P50»).
  3. Revise el mapeo de cada archivoCada archivo tiene su mapeo independiente. Con Copiar al [n] lleva el mapeo al siguiente.
Probar otro mapeo sin releer el archivo

En la Base de datos de XML, el ícono Duplicar escenario copia una carga con su propio mapeo, para probar otra configuración sin volver a leer el archivo (útil con XML muy grandes). El ícono de papelera elimina la carga y sus tareas, con confirmación.

Elegir qué se ve

En el Gantt, abra Filtrar → Selección de tareas. Allí marca qué Categorías 1 (la lista «Escenarios»), qué Categorías 2 y qué tareas se ven. La leyenda de colores y la barra de estado se recalculan con lo que queda visible. Más detalle en Selección de tareas.

«Escenarios» en el panel del Gantt

La lista «Escenarios» del panel de selección del Gantt muestra las Categorías 1, cada una con su color. Para filtrar por el escenario en sentido de esta página (columna Escenario) use el segmentador de la Tabla de Datos o, en la Línea de Tiempo, el menú Escenario.

En la Línea de Tiempo, el menú Escenario filtra por el escenario y edita los títulos de las secciones; su Selección de tareas ofrece las mismas opciones que la del Gantt. En la Tabla de Datos, el segmentador muestra solo las filas de un escenario.

Comparar escenarios

Hay dos formas complementarias de comparar:

  • Entre escenarios: active varios escenarios a la vez en el Gantt. Cada uno se distingue por el color de su Categoría 1.
  • Contra la línea base: active Línea base para ver, en cada tarea, la barra planificada junto a la real o proyectada. En la Línea de Tiempo, el modo Comparador muestra ambas secciones.
Cómo interpretar

Compare la posición de una misma tarea en dos escenarios (o en la Línea Base y el proyectado): si el fin se corre a la derecha, la tarea se retrasó; si el inicio se corre, se desplazó. La barra de estado muestra el inicio, el fin y la duración del conjunto visible.

Vea el diagrama Línea Base frente a Real/Proyectado y el Comparador de la Línea de Tiempo.

Capítulo 8 · Analizar

Análisis y control

Las herramientas de lectura y control con que cuenta OpenGanttLab: indicadores de la barra de estado, avance, ruta crítica, fecha de estado, dependencias y desplazamientos.

En este capítulo aprenderás a:
  • Leer los indicadores de la barra de estado.
  • Usar avance, ruta crítica y fecha de estado para controlar el proyecto.
  • Detectar problemas de datos y de secuencia con los avisos.
Alcance

OpenGanttLab es una aplicación web de visualización y comparación de cronogramas. No calcula valor ganado ni costos y no incluye tableros de gráficos: analiza fechas, avance, ruta crítica y dependencias.

Indicadores de la barra de estado

La barra inferior resume el conjunto de tareas visible.

IndicadorQué significa
TareasNúmero de tareas visibles.
CríticasCuántas están marcadas en la ruta crítica.
Inicio · FinLa fecha más temprana y la más tardía (entre Línea Base y Real/Proyectado).
DuraciónDías entre el inicio y el fin del conjunto.
PorcentajeAvance promedio de las tareas visibles.

Las cifras cambian con los filtros, con los escenarios activos y con las capas Marca Activity y Resumen.

Avance

La capa Avance real rellena cada barra según su porcentaje. Los porcentajes vienen de la columna «Avance %» (0–100) del Excel o de «% Completado» del XML. En Configuración puede hacer que los tooltips muestren, además, los días restantes o vencidos de cada tarea.

Ruta crítica

La ruta crítica se lee de los datos (columna «Ruta Crítica» del Excel o campo «Crítica» del XML): OpenGanttLab no la calcula. Las tareas marcadas como críticas se dibujan siempre con borde rojo; la capa Ruta crítica deja visibles solo esas tareas y sus opciones ajustan el grosor del borde. Con las dependencias activas, las flechas entre dos tareas críticas se dibujan en rojo.

Fecha de estado

La capa Fecha de estado dibuja una línea vertical en la fecha de corte. Todo lo que queda a su izquierda ya debería haber ocurrido; compárelo con el avance. Se configura en Capas (estilo, grosor y color); la Línea de Tiempo usa la misma fecha.

Desplazamientos entre Línea Base y proyectado

Con Línea base activa, la diferencia de posición entre la barra rayada y la de color es el desplazamiento. Si necesita ver las fechas exactas, active Fechas, o agregue al Gantt las columnas «Start LB», «End LB», «Start R/P» y «End R/P» con un clic derecho en un encabezado.

Calidad de la secuencia

El ícono de aviso de dependencias señala problemas que afectan la lectura del cronograma: predecesoras inexistentes, ciclos y textos con formato inválido. Opcionalmente, también los conflictos de fechas. Revíselos antes de presentar un cronograma.

Mover fechas en bloque

Para simular un desplazamiento de un grupo de tareas, use Editar → Mover en bloque. Guarde una copia antes de usarlo: no se puede deshacer. Se explica en Funciones avanzadas.

En este capítulo aprenderás a:

OpciónEfecto

PNG y PDF incluyen las flechas de dependencias si el interruptor está activo, pero no el resaltado temporal de una cadena seleccionada. PPTX no incluye flechas: exporta barras, hitos, líneas y textos.

  • Guardar cambios en el Excel vinculado escribe la tabla en el mismo archivo (Chrome o Edge).
  • Desde la Gestión de XML, el ícono Exportar a Excel descarga toda la base como un archivo .csv (que Excel abre), con las líneas base 0–10.

XML de Project

Desde la Gestión de XML puede crear un XML nuevo con los cambios de la Tabla de Datos (nombres, avance, fechas, predecesoras y campos personalizados) para abrirlo en Microsoft Project. El original no se modifica. Se explica, con sus límites, en Devolver los cambios a Project (XML).

Compartir

Compartir genera un único archivo HTML —una copia de la aplicación con sus datos embebidos— que se abre en cualquier navegador sin el Excel ni el XML originales. Se guarda por defecto como OpenGanttLab_compartir.html.

  1. Prepare el resultadoDeje el Gantt y la Línea de Tiempo como quiere que se vean.
  2. Pulse CompartirEn Chrome o Edge se abre el selector de carpeta; en otros navegadores el archivo se descarga.
  3. Envíe el archivoQuien lo reciba lo abre y ve sus datos y la mayor parte de su configuración; hay excepciones en el Gantt (ver más abajo).
Qué conserva el archivo compartido
  • Las tareas y sus fechas, avance, marca de ruta crítica, ID y predecesoras, y los escenarios (Categorías 1) activos con sus colores.
  • En el Gantt: las capas Línea base, Dependencias, Fechas y Resumen; la escala, la fuente y los tamaños; el orden de los grupos y de las tareas; y los textos libres.
  • En la Línea de Tiempo: las capas y modos activos (Comparador, Segmentación, Ejecutivo, Vista C1, Vista Hitos, Marca Activity, Resumen, Leyenda, Fecha de estado, Ruta crítica y Dependencias), las tareas ocultas, los colores, textos y formas editados, los títulos, el orden de las bandas y el formato de fecha.
Lo que no viaja

En el Gantt no se guardan las capas Avance real, Marca Activity, Fecha de estado y Ruta crítica, las columnas que agregó con clic derecho ni los filtros por columna: al abrir el archivo compartido hay que volver a configurarlos. Tampoco viajan las preferencias de Configuración (por ejemplo el aviso de conflictos de fechas) son del navegador de cada persona, y las columnas de mapeo personalizadas de XML duran solo la sesión.

Cambios sin compartir

El botón Compartir se resalta cuando hay cambios sin guardar. En Configuración puede activar un recordatorio cada N minutos.

  • Preparar la lámina de un comité.
  • Revisar la secuencia de un XML de Project.

Caso 1 · ¿Cuánto se desplazó el proyecto?

Situación: el equipo replanificó y el gerente pregunta qué tareas se corrieron respecto al plan original.

  1. Cargue los datosCargue el Excel o el XML con las fechas LB y R/P (Proyectos y datos).
  2. Active Línea base y Avance realEn Capas o con los accesos rápidos de la barra.
  3. Lea los desplazamientosCompare la barra rayada con la de color; agregue las columnas «Start LB», «End LB», «Start R/P» y «End R/P» con clic derecho si necesita las fechas exactas.
  4. Identifique lo críticoActive Ruta crítica para ver solo las tareas marcadas como críticas en los datos del cronograma.
Resultado

Una vista única con lo planificado, lo proyectado y el avance de cada tarea, donde se ve de inmediato qué se desplazó y cuánto. Vea un ejemplo en Desplazamientos entre Línea Base y proyectado.

Caso 2 · Una lámina para el comité

Situación: hay que presentar el cronograma a un comité en una sola lámina, con foco en los hitos.

  1. Abra la Línea de TiempoElija el modo de vista: Vista C1 para agrupar por disciplina, o Ejecutivo para mostrar solo entregas.
  2. Depure lo que se veOculte con Delete las tareas que no aporten, o use Selección de tareas.
  3. Ajuste la presentaciónEdite colores y textos con doble clic; agregue una llamada o una forma desde Editar. Active Leyenda si hace falta.
  4. ExporteExportar → PowerPoint, o PNG para pegarlo en un informe.
Guarde su trabajo

Use Compartir para conservar la configuración de la lámina. Al abrir el archivo compartido verá exactamente lo mismo.

Caso 3 · Revisar la secuencia de un XML de Project

Situación: llega un XML de Project de varios cientos de megabytes y hay que revisar si la lógica está bien enlazada.

  1. CárgueloEn Datos → Gestión de XML. La lectura por partes evita que el navegador se bloquee.
  2. Complete el mapeoConfirme Categoría 1, Categoría 2, Nombre de Tarea y las fechas. Compruebe con la vista previa.
  3. Active las dependenciasEn el Gantt: Capas → Dependencias.
  4. Revise los avisosEl ícono de triángulo lista predecesoras inexistentes y ciclos. Active el aviso de conflictos de fechas en Configuración si quiere comparar también las fechas.
  5. Siga una cadenaHaga clic en un hito importante para resaltar todo lo que lo precede.
Tiempo de lectura

Los XML grandes se leen por partes y pueden tardar según su tamaño y el equipo. Una barra muestra el avance durante la carga.

Solución de problemas

Síntomas frecuentes, su causa probable y cómo resolverlos.

Importación

Faltan tareas después de cargar el Excel

Una fila se omite si le falta el Nombre de Tarea, la Categoría 1 o alguna de las fechas de Línea Base. Complete esas columnas y vuelva a cargar. Compruebe también que la primera fila con encabezados esté entre las ocho primeras filas de la hoja.

«No es un .xlsx válido»

El lector solo admite el formato .xlsx. Si el archivo es un .xls antiguo, ábralo en Excel y guárdelo como .xlsx antes de cargarlo.

Las fechas salen mal o no salen

Verifique que las columnas de fecha del Excel sean fechas reales y no texto. Puede cambiar el formato de visualización en el selector de la barra inferior.

El XML es enorme y tarda

Los XML grandes se leen por partes y pueden tardar según su tamaño y el equipo. Una barra muestra el avance durante la carga. No cierre la pestaña mientras carga.

El XML no pasa a la tabla

Los campos Categoría 1, Categoría 2 y Nombre de Tarea del mapeo son obligatorios. Mientras alguno esté vacío, verá el mensaje «Completa los campos obligatorios…» y los datos no se cargan. Asigne una columna o un «Valor fijo» a cada uno.

«No parece un XML de Microsoft Project»

El archivo no contiene la sección de tareas de Project. Exporte de nuevo desde Project como XML.

No puedo guardar los cambios en un XML de Project

  • Use Chrome o Edge: la función necesita la API de acceso a archivos.
  • Elija el XML original del mismo proyecto; si el nombre no coincide, la aplicación lo avisa porque los UID podrían no coincidir.
  • El XML original debe estar en UTF-8; con otra codificación no se puede reescribir sin alterar los caracteres.
  • Si el resumen dice «No devuelto», revise el motivo indicado (por ejemplo, una tarea sin elementos de programación manual o una predecesora con un ID que no existe).

Visualización

El Gantt aparece vacío

Aún no hay datos cargados. Vaya a Datos y use Cargar archivo. Si hay datos, revise que haya Categorías 1 marcadas en Filtrar → Selección de tareas y que no haya filtros activos (Filtrar → Borrar filtros).

No veo la Línea Base

Active la capa Línea base (Gantt) o Comparador (Línea de Tiempo) y compruebe que Start LB y End LB tengan fechas.

Faltan tareas en el Gantt

Revise los filtros por columna, la selección de tareas y que Resumen esté activo si busca tareas resumen. Con Marca Activity activo solo se ven las marcadas. En la Línea de Tiempo, mire Tareas ocultas (N).

No veo flechas de dependencias

  • Active Dependencias en Capas.
  • Confirme que las tareas tengan ID y Predecesoras (columnas del Gantt con clic derecho). En XML, revise que el mapeo de «ID (Project)» y «Predecesoras» esté asignado.
  • En la Línea de Tiempo, las flechas no se dibujan en Ejecutivo ni en Vista Hitos.
  • Solo se dibujan entre tareas visibles.

Aparece el ícono de aviso junto a las capas

Es un aviso de calidad de datos, no un error. Haga clic en él para ver las predecesoras inexistentes, los ciclos o, si lo activó, los conflictos de fechas, y corríjalos en la columna Predecesoras de la Tabla de Datos.

Guardar y exportar

No puedo guardar en el Excel

Use Chrome o Edge y vincule el archivo desde Datos. Como alternativa, use Descargar .xlsx.

La exportación a PowerPoint no se genera

La primera vez necesita conexión a internet para descargar el componente de exportación.

Perdí mis cambios de la Línea de Tiempo

Use Compartir para guardar una copia completa. Las tareas ocultas de Ejecutivo y el formato de fecha también se recuerdan por proyecto en el navegador. Las preferencias de Configuración son propias de cada navegador.

Aviso de «cambios sin compartir»

La aplicación no guarda por sí sola si no hay un destino vinculado. Pulse Compartir (o guarde en el Excel vinculado) para conservar el trabajo.

Navegador

OpenGanttLab está optimizado para Chrome y Edge 86 o superior. En otros navegadores puede funcionar, pero algunas funciones (guardar directamente en el Excel, elegir carpeta al compartir) usan una API que no todos incluyen.
